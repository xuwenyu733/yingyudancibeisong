# 宠物小屋 · 存档冲突恢复 v2.36.1

修复本机存档与数据库版本不同后，入口只报错却没有备份、恢复路径的问题。

- 冲突页提供“备份两份存档并进入小屋”：重新读取数据库最新版本，将本机原始副本、同步元数据及数据库副本写入独立本机备份，并校验成功后才加载数据库版本。这个动作不向数据库提交覆盖请求。
- 也可选择“仅下载备份，暂不切换”；恢复后在“更多 → 存档备份”下载历次备份。备份键独立于活动存档，不随正常同步上传，也不自动删除。
- 本机备份空间不足时不切换；载入失败时回滚原本机内容。数据库版本比本机更旧时停止恢复并提示检查数据库。
- 修正未清除的 pending 标记造成的误报：本机内容仍与上次确认的指纹相同时，可安全载入更新的数据库存档。
- 其他窗口修改后，旧房间停止写入与上传，避免把旧内存中的布局覆盖到最新存档。运行中出现冲突时提供重新进入检查的入口。
- 不修改数据库结构。前端 809 项常规测试、后端 49 项常规测试、真实 MySQL 4 组集成测试及严格类型检查通过。真实数据库浏览器流程覆盖两边不同昵称、备份下载、双击保护、恢复、积分/宠物/装修保持一致、备份菜单及再次刷新。
- 当前用户数据库恢复前副本已另外保存于工作区 `work/recovery-backups/`；实际浏览器的本机副本需要通过冲突页按钮保存。自动电脑操作因无法可靠识别浏览器地址而停止，未代替用户点击恢复。

## 使用方式

## 自检发现并修复的问题

1. 自动摆放会把互动书架放到伙伴走不到的角落：新增可达性检查；自动选位同时核对碰撞、边界与伙伴路线，不以传送或穿墙代替走路。
2. 浇水尚未到达时点击走路或座位可能保留旧指令：新操作清除旧请求，结束互动、移动家具、进入装修和离开场景都清理临时动作与道具。
3. 蓝图预览返回路径不直接：增加“返回工坊制作”和“结束预览”，与商店积分兑换清楚区分。
4. 未改动房间也弹出装修码分享：现在只有真实改动并保存才触发；取消和撤销回原样不弹出。
5. 厨房/花园首次打开可能缩成小点：投影尺寸计算前先更新相机世界矩阵，保持比例并适配可见区域。
6. 横屏卡片被底部栏遮挡：分别适配底部栏和手机侧边栏，家具列表独立滚动，关闭按钮保持可达。
7. 新手完成条件与真实动作脱节：装修按前后布局核对，互动按动作到达或实际结果记录。
8. 主题面板和家具玩法面板叠开：打开其中一个会收起另一个。
9. 分享断网的错误反馈：浏览器故障注入验证失败不会消耗食材或播放成功动作，重试成功只扣一份。

| `source-connected/` | 前端源码（宠物小屋 3D 房间，纯 JS + Three.js，无需 npm/CDN） |
| `backend/` | MySQL 数据库后端（Node.js，建库脚本 + schema + 迁移） |
| `deploy/` | Docker / Caddy / 备份等公网部署配置 |

> App 内嵌副本位于 `../uniapp-English/hybrid/html/room/`（由 `sync-room` 脚本从 `source-connected` 同步），两者不要直接改混。

## 快速开始（本机运行）

**前置条件**：Node.js 20+、MySQL 8（本机 3306 端口）。

```bash
# 1. 安装后端依赖
cd backend
npm install
cd ..

# 2. 初始化数据库（创建 pet_room 库 + 独立应用账号，不影响已有库）
#    双击：初始化数据库.cmd，按提示输入 MySQL 管理员(root)口令

# 3. 启动服务
#    双击：启动小屋.cmd（应用账号口令已用 Windows 加密保护，无需重复输入）
```

启动后浏览器打开：

- 小屋：http://127.0.0.1:8899/?storage=mysql
- 数据库目录（查装修码、积分记录等）：http://127.0.0.1:8899/database

## 装修码怎么用

1. 进入"装修"布置好后点"完成保存"，联网时自动弹出 4 位装修码；
2. 朋友进入"装修"→"输入装修码"→ 查看装修，缺的家具会显示价格，确认后一键补齐；
3. 每层独立一个码，号码稳定指向最近一次发布的装修。详见 `装修码使用与自检说明.md`。

## 升级已有数据库

旧版数据库请按顺序先跑：`升级楼层存档数据库.cmd` → `升级中文入口.cmd` → `升级好友数据库.cmd` → `升级装修码数据库.cmd`（每个脚本都会先备份再升级）。

## 公网部署

见 `互联网部署说明.md`（Docker + Caddy + HTTPS 配置已随包提供，需自备云服务器和域名）。
