# 宠物小屋 v2.27.1 · 全面质检与修复说明

本机运行地址：http://127.0.0.1:8899/?storage=mysql 。原页面按 Ctrl+F5 刷新。重启电脑后，双击解压目录里的“启动小屋.cmd”。

仍然无需登录、注册；小屋 ID 自动保留。最多新建两层，扩建二楼消耗 600 积分；每层可备份并新建装修、读取旧布置。好友聊天和只读参观继续保留。

## 本次发现并修复

| 问题 | 修复后的行为 |
| --- | --- |
| 损坏的整屋文件可能覆盖正常小屋 | 写入前校验家具变换、备用房型和台灯支架，错误文件不覆盖原数据 |
| 换小屋 ID 导入时，旧独立布局或附加记录读不回来 | 新导出记录来源小屋，导入时统一映射当前层和命名备份；旧文件继续兼容，原记录保留 |
| 重叠的来源/目标名字可能重复映射附加记录 | 由同一导入校验器映射一次，保留原键内容 |
| 扩建失败、余额不足或重复请求也会增加整屋备份，挤掉旧备份 | 仅成功扩建后保留扣分前副本，失败和重复操作不占备份位置 |
| 移除或屏蔽后重新加友，旧邀请可能重新有效 | 移除/屏蔽时撤销旧邀请，并验证邀请所属的当前好友关系 |
| 检查权限和发送消息/邀请之间存在并发空隙 | 在同一数据库事务和好友关系锁内校验、写入和撤销 |
| 消息游标超过 MySQL 整数范围、404 返回服务器目录 | 校验游标范围，文件错误返回固定中文信息 |
| 聊天草稿串到其他朋友；发送时新输入被清空；较晚历史覆盖新消息 | 草稿按朋友隔离，保留发送期间的新输入，合并历史并过滤过期请求；切回同一好友也正确确认已发送消息 |
| 参观加载中退出后还保留定时器，取消后可能晚出现覆盖层 | 及时取消检查和渲染，创建页面前再次检查取消状态 |
| 好友网络请求长期无响应、等待身份锁时卡住 | 增加有限等待，超时显示中文提示或进入本地小屋 |
| 装修栏瞬时滚动后箭头晚一帧更新 | 同一次操作立即更新箭头状态，保留平滑滚动事件处理 |
| Windows 相对配置路径和端口提示不正确，隐藏启动可能卡在口令输入 | 统一绝对路径、按实际端口显示链接，非交互模式缺口令时明确停止 |
| Docker 健康检查未覆盖数据库，浏览器管理说明与实际不符 | 同时检查应用与数据库，增加私有连接的中文只读查询脚本；说明已有卷的显式升级步骤 |

## 数据库与部署边界

本次无需新增数据库表或执行结构升级，仍为数据库结构 1.3.1（36 张表、17 个视图）；应用后端版本为 1.4.0。原有存档的内容哈希、修订号及其业务记录数量已复核不变，其他已有小屋也保留。测试仅使用临时小屋，结束后清理。

商城和扩建使用学习/体验积分，没有人民币、微信或支付宝支付接入。

本机服务可直接运行。当前没有云服务器和域名，也没有 Docker 引擎；容器启动、证书和真实公网连通仍需部署到服务器后验证。本次完成了配置、脚本和行为测试。详细操作见“互联网部署说明.md”。

Docker 内查看数据库请使用 deploy/view-database.sh 的固定中文只读入口；Windows 本机仍可通过 /database 页面查看。未开放公网数据库管理接口。
