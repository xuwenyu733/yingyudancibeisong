# 宠物小屋 · 四位装修码版 v2.28.0

打开即进入，已删除登录和注册。小屋最多新建两层，一楼扩建二楼需要 **600 积分**，成功时只扣一次；积分不足不会扩建或扣费。已有旧版楼层和存档完整保留，新版本不能继续加层。

## 4位装修码：把这套摆设分享给朋友

1. 进入“装修”，摆好家具，点“完成保存”。联网后会自动弹出当前楼层的4位装修码。
2. 把数字告诉朋友，例如 `0007`；开头的0也必须输入。同一层更新装修后号码不变，朋友复制的是最近一次发布的版本。
3. 朋友进入“装修”，点“输入装修码”，输入4位数字，再点“查看装修”。
4. 已拥有的物品免费复制；缺少的家具、地板和必要的大房型升级会逐项列出价格、总积分和当前余额。
5. 确认后点“一键购买缺失物品并复制”；不需要购买时点“备份并复制摆设”。取消不扣积分，积分不足不操作。
6. 系统先备份这一层的旧装修，再完成购买和复制。备份最多5个，已满时先整理；不会自动删除旧装修。可在“城堡 / 楼层”读取旧装修。

仅分享当前楼层的摆设、颜色、地板与装修手绘。账号信息、照片、积分、好友和旧备份不分享。个人成就专属纹样不转移；限定礼物需要接收者自己解锁且仍有效，否则说明原因并停止，不扣积分。复制保留自己的房名、宠物与另一层；新买家具在另一层先放仓库。手绘会随装修公开，请仅发布愿意分享的作品。

装修码要在连接同一个服务器的玩家之间使用。当前未部署公网，异地朋友需要以后打开同一个公网网址。4位数字共10000个位置，每位玩家每层占一个；满额时会明确提示，不覆盖别人。离线时可继续本地装修，连接恢复后再发布或复制。

## 同一层换一套新装修

1. 打开“城堡 / 楼层”，选择要改的一楼或二楼。
2. 在“这一层的小世界”填写存档点名字，例如“原来的书房”。
3. 在“换一套新装修”填写新房间名字，例如“森林阅读屋”，选择奶油、薄荷或糖果风格。
4. 点“备份并新建装修”，核对提示，再点“确认备份并新建”。旧布置和新装修在同一次保存中处理，备份失败不会清空房间。
5. 新房间从空白开始，当前层的家具收入仓库，可按喜好重新摆放。已购买的家具、当前房型和已解锁的大房型、积分、宠物与另一层保留。
6. 想回到原来的布置，在这一层的备份列表点“读取”，再确认。读取前若想保留新装修，先用“保存此层”给它另存一个名字。

一楼、二楼各自保留最多 5 个命名备份，不会互相覆盖。备份满时，先导出需要保留的当前装修，再删除不需要的备份腾出位置；导出文件本身不会释放备份位置。系统不会自动删除旧备份。新建装修不增加楼层，也不再次扣除扩建二楼的积分。

## 数据库和保存

本次新增 `social_room_designs` 保存公开装修和稳定的4位码；`room_world_saves` 已能分别保存各层当前装修和命名备份，`wallet_receipts.points_delta` 保存本次扩建实际扣除的 -600 积分。新扣分记录写明金额，旧记录没有保存金额的继续显示“未记录金额”，不会反推或追扣。

在 Navicat“视图”中打开“新手_03_房间存档”看新旧装修，打开“新手_06_积分记录”看扣分。数据库结构版本为 1.4.0，共 36 张表、17 个视图；应用后端版本为 1.4.0。装修码复制的购买/房型升级也记录实际扣除积分。原始存档内容、版本号和业务数据不因程序升级而改变。

修复了保存响应丢失后继续装修容易出现版本冲突的问题：下次同步先确认上一次提交内容，再接续新的修改；另一窗口保存了不同内容时仍保留冲突保护。

## 当前电脑体验

1. 解压整个包，双击 `启动小屋.cmd`。
2. 打开 `http://127.0.0.1:8899/?storage=mysql`，直接进入小屋，没有登录、注册、密码或账号选择页面。
3. “个人主页”和“朋友”面板自动显示专属 `PET-…` 小屋 ID，复制给朋友即可添加。
4. 对方同意申请后可聊天、邀请参观各层。朋友同样直接打开网址使用。

同一浏览器下次打开沿用原小屋、ID 和好友。普通标签页共享同一个小屋，两个不同浏览器或无痕窗口可体验不同小屋。浏览器会私下保存识别自己小屋的凭据；公开 ID 不能用来修改别人的小屋。清除网站数据、换浏览器或无痕窗口关闭后可能获得新 ID，请定期导出庄园备份。

网络暂时不可用也能直接进入浏览器本地小屋，装修和楼层会保留。连接恢复后刷新，自己的本地装修会复制到自动生成的小屋中；服务器已有的小屋仍优先使用，不覆盖别人的数据。旧版电脑上的原存档与本地副本不删除。

当前电脑已完成数据库 1.4.0 装修码升级，旧记录保留。其他电脑已有旧库时，依次补齐楼层、中文入口、好友升级，再运行新包的“升级装修码数据库.cmd”；脚本先备份再升级。新电脑使用“初始化数据库.cmd”。

后台任务或隐藏窗口启动时可加 `-NonInteractive`；没有可解密的数据库口令会明确退出，不会停在看不到的输入框。若换了 Windows 用户、电脑或运行身份，请在那个身份下重新运行普通启动脚本配置口令。通过 `PET_ROOM_MYSQL_CONFIG` 指定配置时，路径按启动时的工作目录解析；运行链接会跟随配置的 `httpPort` 或环境变量 `PORT`。

## 朋友操作

- 主页和朋友面板可复制 ID。无需登录注册，不设置密码。
- 申请要对方同意才成为好友，之后可私聊。支持纯文本、未读数量和断线重试去重。每次打开显示最近 100 条，聊天保存在服务器。
- 好友列表点“邀请参观”，对方在“参观邀请”中点“接受并参观”。邀请有效 30 分钟，主人可以结束。
- 访客可切换查看主人已保存的各层装修。访客使用临时只读场景，不能修改主人小屋，拿不到积分账本、私人资料、照片、备份或聊天。参观展示进入时的布置；主人修改后，重新进入可看最新版本。
- 访客点“返回我的小屋”离开；移除好友或屏蔽后不能继续聊天、参观。主人结束邀请后，访客通常在下一次权限检查时返回（约 5 秒）。

各层独立装修和命名存档仍保留，商城继续使用学习/体验积分。

## 部署到云服务器

准备可运行 Docker Engine 和 Docker Compose v2 的 Linux 服务器及域名。域名 A 记录指向服务器公网 IPv4；配置 AAAA 时也要保证 IPv6 可达。防火墙、云安全组放行 TCP 80、443。SSH 端口按自己的管理需要开放。中国大陆服务器按服务商要求完成备案。

上传整个解压目录，例如 `/opt/pet-room`。不要上传本机数据库备份和 `backend/mysql.password.dpapi`；云端生成独立口令和数据库，Docker 构建也会排除这些文件。

### 生成配置

项目根目录运行，换成真实域名：

```sh
node deploy/generate-env.mjs room.example.com
```

只有 Docker、没有 Node.js 时：

```sh
cd deploy
docker run --rm -v "$PWD:/setup" -w /setup node:24-alpine node generate-env.mjs room.example.com
cd ..
```

脚本创建 `deploy/.env`，两组数据库口令分别随机生成，不会覆盖原文件。妥善保管，不要公开或重新生成已经在用的数据库口令。

### 启动

```sh
cd deploy
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

第一次拉取镜像、建表并导入商品目录。等待 db、app 健康、web 启动，打开 `https://你的域名`。Caddy 会为可访问的域名申请 HTTPS 证书。朋友打开相同网址，各自自动进入自己的小屋。

数据库只在 Docker 内部网络可达，应用端口只绑定服务器 `127.0.0.1:8899`，公网通过 HTTPS。Cookie 使用 HttpOnly、SameSite，公网配置另有 Secure。应用使用只能读写数据的数据库账号。

应用健康检查会同时检查 HTTP 服务和数据库连接；仅网页进程还在运行而数据库已断开时，不会继续报告健康。

### 搬迁旧进度

云端首次启动为空数据库。在本机主页导出完整庄园备份，再打开云端网址、导入备份，便能搬入各层进度。此方式会得到新的云端 ID，原电脑数据保留。

需要保留原 ID、好友和聊天时，由维护人员在停止写入并备份后做整库迁移。恢复 SQL 会影响目标库数据，不能直接导入已有其他用户的服务。数据库管理接口只允许服务器本机访问。

### 备份和维护

在 `deploy` 目录：

```sh
sh backup.sh
docker compose ps
docker compose logs --tail=100 app web
docker compose stop
```

备份在 `deploy/backups`，含小屋身份、聊天和装修，请复制到安全位置。停止不会删数据；不要执行 `docker compose down -v`，它会删除持久卷。修改 `.env` 不会自动修改已有 MySQL 账号口令。

Windows 原生启动的数据库目录是 `http://127.0.0.1:8899/database`。Docker 桥接会改变来源地址，容器版会拒绝该浏览器管理入口，SSH 转发也不能绕过这条限制。容器版在服务器的 `deploy` 目录用下面的只读中文查询脚本：

```sh
sh view-database.sh guide
sh view-database.sh accounts
sh view-database.sh saves
sh view-database.sh points
```

分别查看使用指南、小屋 ID、房间备份和积分记录。另支持 `floors`、`friends`、`invites`、`designs`（装修码）。只查询预设中文视图，每次最多 100 行，不需要输入数据库密码，也不会开放公网管理端口。

### 更新已有 Docker 数据库

MySQL 只在首次建立空数据卷时运行初始化 SQL；以后更换程序包不会自动升级已有数据库。更新前先停止写入、成功备份；数据库已为 1.3.1 时升级到 1.4.0（装修码），在 `deploy` 目录执行：

```sh
docker compose stop web app
sh backup.sh
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot --default-character-set=utf8mb4 pet_room' < ../backend/migrations/1.4.0-design-codes.sql
docker compose up -d --build
docker compose ps
```

数据库为 1.3.0 时先补 1.3.1-direct-entry.sql，再补 1.4.0-design-codes.sql。更早的结构按迁移版本从旧到新补齐，不能跳过前置结构；不要删除数据卷来解决升级问题。恢复整库 SQL 应由维护人员在停止写入、保存目标库备份后操作，恢复前核对目标数据库，避免覆盖正在使用的数据。

## 看数据库

结构版本 1.4.0，共 36 张表、17 个视图。Navicat 展开 `pet_room` →“视图”：

| 中文入口 | 内容 |

| 新手_12_装修分享 | 四位装修码、主人、楼层和发布版本 |

## 自检与测试

本机真实 MySQL 和两个独立浏览器已检查免登录直接进入、ID刷新保留、断网本地保存、好友同意、双向聊天、文本注入、访问权限、两层参观、主人撤销、刷新再次进入和存档隔离。临时测试账号已清理。

Docker 配置另做静态解析和构建文件检查；此电脑没有 Docker 引擎，未完成容器启动、公网或证书验证，需部署后验证。

后端 `cd backend` 后 `npm test`。真实存储测试需显式设置 `PET_ROOM_MYSQL_INTEGRATION=1`，好友测试需 `PET_ROOM_SOCIAL_INTEGRATION=1`，它们会创建并清理临时记录，建议使用测试环境。前端 `cd source-connected` 后运行 `node --test tests/*.test.mjs`，浏览器测试需 Playwright 和 Chromium/Edge。
