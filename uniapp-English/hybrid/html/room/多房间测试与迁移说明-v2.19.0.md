# v2.19.0 多房间测试与迁移说明

日期：2026-10-28。本轮按用户确认实现：**一键全收进仓库，所有房间共用积分；设计者锁定音乐曲目，用户保留静音与音量控制。**

## 打开测试版

解压后双击 `StartEstatePreview.cmd`，或执行：

```text
python serve.py --port 8870 --preview estate
```

以终端实际打印的地址为准。当前工作区测试地址：`http://127.0.0.1:8870/?preview=estate`。仅当前电脑可访问。

测试版使用独立的 `original-pet-room-estate-qa-v1` 存档空间，初始50,000体验积分。不会把测试进度写进另一边的新项目。旧单房模板仍可用 `?preview=qa` 打开。

## 当前完成

- **一键全部收纳**：只收当前房间可入仓库的家具，积分、收藏、宠物保留；地砖和固定名牌/成长花园保留。台灯先收起，避免支架依赖。一次账本提交；失败恢复原对象、灯、布局。收纳后可从仓库免费摆回。
- **默认归位**：单独入口，需确认。只恢复当前已摆放家具的默认位置，不复活仓库里的家具；归位产生碰撞时拒绝并保留原布局。
- **独立房间**：最多6间，当前原型开新房免费；奶油、薄荷、糖果三种起始模板。房间名字、布局、仓库状态、配色和家具创作独立保存。
- **共享账户**：全部房间共用积分、家具收藏、宠物收藏、学习奖励、主人资料和成长记忆。新买家具在购买房间摆放，在其他房间默认放入仓库；同一件收藏可在不同房间独立摆放，不会再次扣费。
- **小院与城堡**：小院平铺，城堡按楼层叠放卡片。新房可选择是否叠到上一层。点击楼层进入相应房间，切换前会阻止未完成装修和交易。模型加载失败会尝试回到原房间。
- **家具获取时间**：图鉴点击已拥有家具，显示获取者、日期、时间和“到家第N天”；当天为第1天，按当地日历日期计数。旧收藏没有可信日期时仍显示日期未记录。
- **背景音乐**：原创24秒柔和循环“云朵小屋”，无外部音频依赖。设计者在 `designer-config.mjs` 中配置曲目；界面与运行API不提供切歌。沿用静音和轻声/标准/响亮；必须用户手势解锁，页面隐藏后暂停，跨房间保持同一音乐实例。
- **互动框架**：`interaction-framework.mjs` 输出版本化事件计划，涵盖摆放、旋转、购买、学习、签到、徽章、回访、夜间、礼物、收纳、归位和换房。音效已由计划统一驱动；现有场景动作与文案仍在工作，宿主可通过 `onInteraction(plan)` 接收迁移信号。
- **完整庄园存档**：家长高级区导出/备份的是所有房间、共享积分、伙伴状态和全局个人主页；导入失败回滚。完整备份保存在外层独立键，不嵌入自身，避免递归膨胀。

## 给另一边新版本的接入合同

新版本尚未接入。本轮仅实现当前模板并准备可迁移模块，等待确认目标项目目录/聊天及其最终版本。

```js
import {mountPetEstate} from './estate-house.js';

const estate = mountPetEstate({
  container: document.getElementById('app'),
  storageKey: 'your-existing-namespace',
  initialPoints: 0,
  onInteraction(plan) {
    // 将标准事件计划交给新版本的动画、音效与气泡层。
  },
});
await estate.ready;
estate.api.getEstate();
await estate.api.createEstateRoom({name:'薄荷书房',template:'mint',stacked:true});
await estate.api.selectEstateRoom('room-1');
estate.api.setEstateMode('castle');
await estate.api.collectAllFurniture('unique-request-id');
estate.api.getMusic(); // 只读曲目信息；音量/静音沿用updateCompanion。
estate.dispose();
```

- 使用同一个 `storageKey` 时，首次建立庄园会读取原来的 `-account-v1`、`-companion-v1`；只写新的 `-estate-v1`，不删除旧键。个人主页键全局共享。
- 各房间通过 `storageForRoom()` 对接原来的 `mountPetHouse`，不用让渲染器知道共享积分内部结构；房间交易回执与全局交易回执分开，避免扩建历史污染其他房间。
- 稳定的外层API会转发到当前房间，换房后无需宿主重新保存API引用；事件计划和楼层信息都有明确版本与类型声明。
- 导出格式为 `pet-estate-save`。旧单房JSON不会直接覆盖一个已有的多房间庄园；先在旧版导入，再以原命名空间进行迁移。
- 旧的跨窗口command桥仍沿用原命令表。新增庄园命令当前通过显式JS API调用；若新宿主依赖跨窗口消息，需要在新版本桥中补充命令白名单、参数校验和来源检查，不能直接开放任意函数执行。

## 仍是基础版 / 尚未完成

1. 城堡目前是楼层组织界面加逐房间3D切换，不是整栋城堡同屏3D外观；没有楼梯行走、连续穿楼和结构编辑。
2. 免费房间上限6间，尚无付费扩房规则；按用户选择保持所有房间共用积分。
3. 音乐锁定针对产品界面和公开运行API；这是本地原型，不声称静态源代码具备服务端权限防护。
4. 另一边的新版本尚未定位和迁移，不能宣称已联调；本包包含接口、类型、原子存储适配器和迁移说明。
5. 上版尚未制作的自由画笔、多阶段成长模型、叼礼物回家、蜷睡打呼、完整搬家运镜等仍未补做；本轮没有用菜单入口冒充这些动画。
6. 没有新增云同步或服务端积分防篡改，也未完成真实iOS/Android、多浏览器和长期运行验收。
