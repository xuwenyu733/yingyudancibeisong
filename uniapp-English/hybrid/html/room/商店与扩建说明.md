# v2.3 · 积分商店与房屋扩建

新增功能：用学习积分兑换家具，并用积分逐级扩大房屋。原 v2.2 压缩包未改；本目录为独立新版。

## 快速体验

双击 `StartPreview.cmd`（需要 Python），或运行 `python serve.py`。打开页面右上角“商店”，切换“家具 / 扩建 / 积分”。独立演示首次提供 **1,000 体验积分**；“积分”页可模拟新学、复习和签到，每项每天模拟领取一次。它不是已接入真实学习系统的账户。

**积分来源（v2.5 起）**：学习奖励（`creditLearning`，每项每天一次）、每日签到（随连续天数递增，每满 7 天加周期奖励）、升级奖励（每次升级发放一次）。三者在账本里分属独立幂等表（`learning/requests/rewards`），同一 `eventId` 不会重复入账；签到与升级积分在“待入账”里合并结算，账本忙时下次打开主页自动补账。学习时长与经验只在 `creditLearning` 时联动累计，不能凭空领取。

家具兑换后自动寻找可摆放且不阻断座位通路的空位。进入“装修”可以继续拖动、旋转和修改碰撞盒；仍不显示碰撞线、网格或选择线。没有空位、余额不足或保存失败均不会扣分。当前四种商品每种最多拥有一件，不含背包收纳/转售功能。

| 商品 | 示例价格 |
| --- | ---: |
| 四叶草盆栽 | 120 |
| 阅读书架 | 260 |
| 云朵小桌 | 180 |
| 月亮摆件 | 220 |

这四件是新增原创程序几何，不增加外部模型下载。原有沙发、台灯等作为初始家具保留。

| 房级 | 实际宽 × 深 | 升到本级的积分成本 |
| --- | --- | ---: |
| 初始小屋 | 8.8 × 8.2 | 0 |
| 温馨大屋 | 10.8 × 10.2 | 600 |
| 宽敞大屋 | 12.8 × 12.2 | 1,500 |

扩建会改变地板、后墙、窗及装饰画位置、摆放和行走边界、相机适配范围；人物和已有家具的尺寸、坐标不会跟着放大。房级逐级购买。价格、房级尺寸和学习奖励均集中在 `economy.mjs`，目前是示例数值，可根据你们的学习节奏调整。

## 接入学习 App

```js
import {mountRoom} from './room.js';

const room = mountRoom({canvas, uiRoot, initialPoints: 0});
const api = await room.ready;

// 由宿主确认学习完成后调用。eventId 应为稳定且唯一的真实完成记录编号。
api.creditLearning({eventId: 'lesson-completion-001', learned: 10, reviewed: 5});
api.creditLearning({eventId: 'check-in-user-001-2026-10-26', checkIn: true});

// 成功和失败都返回 {ok, code, message, state?}。
await api.purchaseFurniture('clover-planter', 'purchase-request-001');
await api.expandRoom('expansion-request-001');
api.getShop();
```

奖励示例：新学每词 10 分、复习每词 5 分、签到 20 分。单事件新学/复习各最多 100 词。重复完成记录不会重复加分；重复成功交易编号不会再次扣费。宿主必须保证学习记录、签到日期和交易编号的可信性，不能仅依据客户端自行上报认定真实学习。

核心 `mountRoom` 默认初始积分为 **0**。`bootstrap.js` 仅演示时显式设置 1000，并加载 `createShopPanel({root,api,pointsLabel:'体验积分',demo:true})`。正式 UI 使用 `demo:false`，不显示模拟领奖按钮，并引入 `shop.css`。UI 更新时调用 `shop.update(state)`，销毁调用 `shop.dispose()`。

消息桥增加 `getShop`、`purchaseFurniture({sku})`、`expandRoom({})` 三条指令，交易使用消息 envelope 的 requestId 作为账本幂等编号。`creditLearning` 不开放给通用 room-command，宿主通过受控接口调用。

## 保存与失败处理

- 新账户以 `${storageKey}-account-v1` 为键，将积分、产权、房级、家具布局和已处理记录放进同一个 JSON，一次成功写入后才认定交易成功。
- 旧的 v3 房间布局在没有账户布局时读取；首次实际保存/交易后进入新的账户快照。保留旧键，不删除旧存档。
- 注入 `storageAdapter` 仍需同步 `getItem/setItem`；异步云接口应由宿主维护本地同步缓存后再同步服务器。`storageAdapter:null` 仅内存演示，刷新不保留。
- `persistLayout:false` 仅关闭装修完成时的自动保存；购买、扩建和学习奖励属于显式账户交易，仍保存完整账户。需要完全不落盘时用 `storageAdapter:null`。
- 装修期间禁止购买/扩建；装修中持久化导入暂存在会话内，完成时统一写入，取消不影响原存档。
- 账户中的已购家具必须连同布局恢复。已有产权时，即使传入 `restoreLayout:false`，也恢复账户布局，避免家具叠放。若账户布局非法，返回 `ACCOUNT_LAYOUT_INVALID`，不会覆盖原积分或存档。
- 写入失败会撤销新增家具、扣分或房壳变化，可在存储恢复后重试。交易中的临时布局不发送给宿主，成功后发出最终变化事件。

当前仍是本地原型账本。正式跨设备积分、学习凭证校验、账号资产和并发扣分需要接入你们的服务端；未提供这些后端，也未完成 uni-app Android/iOS 真机联调。
