# v2.5 接入更新：个人主页 · 等级 · 签到 · 勋章墙

## 新增房间 API（`api`）

```js
api.getProfile()        // → {ok, profile:{gender,name,xp,level,levelName,totalStudySeconds,streakDays,totalCheckIns,
                        //    lastCheckIn,todayChecked,todayReward,tomorrowReward,levelInfo,badges[],balance,valid,error}}
api.checkIn()           // → {ok, streak, exp, points, levelUps, pendingPoints, message}
api.setProfileGender('male'|'female')
api.setProfileName(name)      // ≤40 字符
api.addStudyTime(seconds)     // 0–86400，累计到“学习时长”展示与学习勋章
```

- 积分账本新增 `economy.reward({eventId, points, reason?})`：通用幂等入账（与学习事件分开去重），签到/升级奖励都走它；`eventId` 唯一即可防重复，旧存档自动补 `claims.rewards:[]`。
- 个人主页账本独立存档 `storageKey + '-profile-v1'`，与积分账本同款同步事务；`getProfile()` 每次会先把“待入账积分”补进 economy（账本忙时下次自动重试，不会多发）。返回里的 `calendar` 为当月每日 `{date,day,checked,isToday}`，由 `buildMonthCalendar(checkInDates, 今天)` 组装（纯函数，可独立测试）；`checkInDates` 签到历史上限 480 天，旧存档自动补空数组。
- 等级：1–20 级，升级经验逐级 +60（1→2 需 100）；升级奖励 50/75/100…（`economy.reward`，`eventId:'levelup:N'` 由签到流程自动入账）。经验只在签到与学习联动时增长——本包不提供“凭空加经验”的 API，正式 App 由服务端下发经验。
- 签到奖励公式见[改版说明](改版说明.md)第二节；同一设备同一天只能签一次（本地日期判定，跨时区由宿主自行归一）。
- 事件：`checkin-done` / `level-up` / `badge-unlocked` / `profile-change`（个人主页账本变更）。勋章判定 `badgeTest` 与目录 `BADGES` 导出在 `profile.mjs`，可自行扩展（加一项 `{id,name,description}` + 一条判定分支）。
- 学习时长联动：`creditLearning` 成功时按 `learned×20 分钟 + reviewed×10 分钟` 累计；不想联动可在宿主侧改调 `addStudyTime`。
- 桥接白名单新增 `getProfile / checkIn / setProfileGender / setProfileName / addStudyTime`，参数在桥接层校验（性别枚举、昵称 ≤40、时长 0–86400、无多余字段）。
- 并发写保护：profile 与 economy 账本落盘前重读一次，外部（另一标签页）已写则返回 `ARCHIVE_CONFLICT` 拒绝本次写入，重载后以存储为准（安全优先，不自动合并）。
- 时区：`mountRoom({ timeZone: 'Asia/Shanghai' | 'UTC' })` 指定签到「今天」的 IANA 时区，缺省设备本地；无效时区名自动回退。
- 满级语义：等级 20 后签到 `exp:0`（积分照发），`checkIn` 返回 `capped:true`；`nextBadgeHint` 提供「下一枚可量化勋章还差多少」提示，`stats` 提供本月/近 30 天签到统计，`checkInDates` 提供完整签到日期（前端本地做日历翻月）。
- 庆祝姿势：`api.checkIn()` 成功或购买/扩建解锁新勋章时，若角色 pose 提供 `setCelebrate` 会触发约 1 秒的点头摇尾（可选接口，缺失无影响）。
- 服务端账本联调：`server-proto/` 提供 HTTP 协议（`proto.md`）、参考服务端（`mock-server.mjs`）与桥接客户端示例（`mock-client.mjs`）。本地评测页默认仍走 localStorage 账本；接入真实后端时按协议实现并替换 baseUrl 即可，UI 不用动。
- `room.d.ts` 新增 `ProfileState / ProfileBadge / ProfileCalendarDay`；版本字段现为 **2.6.0**。演示页右上角「Lv.n」入口为 `scene-profile.js`（纯视图，只调上述 API）。

## v2.6 接入更新（日历翻月 / 勋章弹层 / 服务端账本原型）

- **跨月日历**：`getProfile().profile.checkInDates` 返回完整签到历史（升序，上限 480 条）；前端拿它 + `buildMonthCalendar(checkInDates, today, 'YYYY-MM')` 即可本地渲染任意月份，面板「‹ 年月 ›」翻页不再打接口。`buildMonthCalendar` 第三参缺省=当月（向后兼容），跨月视图无 `isToday` 标记。
- **勋章解锁弹层**：纯视图侧本地 diff（上次已解锁集合），不新增接口；`applyProfile` 每次刷新都会对比，打开面板时也会补弹尚未展示的新勋章。
- **服务端账本联调原型（`server-proto/`）**：`proto.md` 定义 `POST /api/v1/command` 协议，命令 `creditLearning / checkin / purchase / expandRoom / query`，幂等与校验规则齐全；`mock-server.mjs` 是纯 Node 参考实现（多用户隔离、事件/签到按业务判重、购买/扩建按 requestId 重放）；`mock-client.mjs` 的 `RoomServerClient` 把桥接命令映射成 HTTP。接入真实后端：实现同一协议并替换 baseUrl 即可，UI 与桥接层不用动；本地 localStorage 账本保留为离线降级。
  - 快速体验：`node server-proto/mock-server.mjs [port]` 独立自检，`node server-proto/mock-client.mjs [port] [userId]` 走一遍 HTTP 链路。

## v2.7 接入更新（按钮布局 / 勋章进度 / 消费统计）

- **HUD 布局**：商店钱包与商店按钮合并到左上角 `room-shop__topbar` 一行；右上角 `room-hud-right`（个人主页等级徽章）独占，不再重叠。宿主如需自定义顶部工具条，按 `.room-shop__topbar`（flex 行）组织即可。

- **日历交互**：翻页后点击标题或按 Enter/Space 回到当前月份（纯视图侧）。

# v2.4 接入更新：花盆浇水

**桥接白名单（v2.4 补齐）**：`createRoomBridge` 的 `COMMANDS` 现在包含 `getShop` / `purchaseFurniture` / `expandRoom` / `creditLearning` 全部四项。`creditLearning` 参数为 `{eventId, learned?, reviewed?, checkIn?}`：`eventId` 必填标识符，`learned`/`reviewed` 为非负整数（默认 0），`checkIn` 为布尔（默认 false），至少一项为真；多余字段直接 `INVALID_PARAMS`，不会到达账本。

可浇水目标：地面盆栽 `floor-pot`、商店四叶草盆栽 `shop-clover-planter`（买到后同样可浇）。悬停盆栽提示「给花浇水」（浇完 6 秒内显示「刚刚浇过水」），**点击才动作**：无论狐狸坐在沙发/软凳、正在走向别的座位还是正在走路，都会自动起立/改道，走到盆栽前弯腰浇水约 1.7 秒（盆栽上方落淡蓝水珠）。浇水期间按移动键立即取消。

- 状态：`getState().watering`（bool，是否正在浇水）、`waterTarget`（目标盆栽 id，`null`=无）；`petState` 会出现 `'watering'`。
- 事件：`water-start` / `water-done`（带 `targetId`）/ `water-blocked`（盆栽被围死、无可达落点）。
- 浇水姿势：浇水期间角色会用 `pose.setWatering(0–1)` 叠加“端水壶”手臂姿态（肩前伸、肘微屈、颈微低、尾微翘），结束后恢复；该方法是原创造型的新增可选接口，0 权重时与原本行为完全一致，不影响 `sit/stand` 关键帧契约与 GLB 动画。
- 键盘：悬停时按 Enter 触发「坐下/开灯/浇水」（与点击同一条 `triggerInteraction` 路径）；Space 可取消浇水。
- 落点换算在 `seats.mjs`：`WATER_TARGETS`（目标表）+ `fitWater` / `resolveWaterApproach`；想加第三个可浇目标，往 `WATER_TARGETS` 加一项并给对应 Group 打 `interaction:'water'` / `waterTargetId` 标记（商店家具购买时会自动打标）。
- 商店摆放：购买家具的候选落点由 `placement.mjs` 的 `placementOrder(bounds, step)` 提供（靠墙优先排序），可独立测试；需要自定义摆放策略时替换这一个函数即可。
- 版本字段现为 **2.4.0**。

# 接入说明 · v2

## 最小接入

运行时不需要 npm、CDN、import map 或全局 Three.js。把完整目录放到你的静态资源服务中，在支持 ES Modules、WebGL2、Pointer Events 的浏览器/WebView 中使用。

```js
import {mountRoom} from './room.js';

const room = mountRoom({
  canvas: document.querySelector('canvas'),
  assetsBaseUrl: new URL('./assets/', import.meta.url).href,
  quality: 'auto', // low / balanced / high / auto
  storageKey: 'my-app:room:user-123', // 不同账号/实例使用不同键
  onEvent(type, detail) { console.log(type, detail); },
});
const api = await room.ready;
api.setLamp(false);
api.walkTo(0, 2);
api.toggleSofa();
const saved = api.getLayout(); // 纯JSON，不包含Object3D/纹理/函数
// 卸载页面、Vue onBeforeUnmount、React effect cleanup中执行：
room.dispose();
```

`mountRoom` 不自动查找页面控件，也不向 `window` 写变量。导入模块不会创建渲染器。一个 canvas 同时只允许一个实例；销毁后可以重新挂载。加载中销毁会让 `ready` 以 `ABORTED` 拒绝，请处理 Promise。初始化和资源超时会返回带 `code` 的错误。

需要演示装修面板时，先引入 `room.css`，用 `createRoomView(container)` 创建独立视图，再把 `view.canvas`、`view.controlsRoot` 传入。样式限定在 `.pet-room-view` 内。可参考 `bootstrap.js`。未传 `uiRoot` 时使用无UI装修会话，宿主自行做按钮和面板。

## 布局与存储

```js
await api.setDecorationMode(true); // 伙伴会先安全起立落地
api.setFurnitureTransform('table', {position:[-0.6,0,0.87]});
api.setFurnitureCollider('table', {size:[0.95,0.411,1]}); // 家具局部坐标
const result = api.importLayout(saved); // {ok,reason}，失败整笔回滚
api.setDecorationMode(false);
```

变换、调盒、导入需在伙伴 `idle` 且没有拖动时进行。碰撞与沙发通路都要校验；失败不会穿模硬放。`getLayout()` 是 v3 数据，原来的同源本地布局仍可继续使用。

默认存储为当前站点 localStorage。宿主可注入同步 `storageAdapter: {getItem(key), setItem(key,value)}`。使用后端存档时可设置 `persistLayout:false`，监听布局变化后自行上传 `getLayout()`；初始化后用 `importLayout()` 恢复。`storageAdapter:null` 禁用本地存储。服务端账号、积分、家具所有权与云同步不属于场景模块。

存档限制 UTF-8 256KB、深度12，并拒绝函数、循环、访问器、非有限数、巨大变换及无效盒体。不要直接修改 `getFurniture()` 返回对象后期望碰撞自动同步；该接口仅供调试。

## 消息协议与 uni-app

`integration.mjs` 提供版本1协议和白名单指令。显式创建桥接：

```js
import {createRoomBridge} from './integration.mjs';
const bridge = createRoomBridge({
  api, getState:api.getState, eventTarget:canvas, roomId:'room-a',
  onEvent(envelope) { /* 在这里接宿主消息发送函数 */ },
});
await bridge.ready();
canvas.dispatchEvent(new CustomEvent('room-command', {detail:{
  protocolVersion:1,roomId:'room-a',requestId:'request-001',
  type:'command',command:'setLamp',params:{on:true},
}}));
// 结果从 room-event 返回，以 requestId 对应；卸载时先 bridge.dispose()。
```

白名单：`setLamp`、`toggleSofa`、`walkTo`、`setDecorationMode`、`setFurnitureTransform`、`setFurnitureCollider`、`getState`、`getLayout`、`importLayout`。默认不监听跨文档消息；如确需 iframe/postMessage，显式给出 `messageTarget`、`allowedOrigins` 和来源 Window 白名单，不使用 `*`。

uni-app 原生端建议用 WebView 承载此目录，宿主加载其对应 SDK 并在桥接就绪后转发协议；核心不直接依赖 `uni`。当前没有接入你们实际 App 工程，Android/iOS 真机、宿主 SDK 握手及打包路径还需按实际工程联调，不能把浏览器自检视为原生兼容认证。

独立演示页保留 `window.PetRoom`，且仅在旧名未占用时保留 `window.HamsterRoom` 别名。新的项目应通过 `mountRoom` 返回值接入。

## 角色与其他引擎

默认原创角色在 `characters/original-fox.js`，无需加载旧仓鼠。可通过 `characterFactory` 注入其他角色，返回 `{model,pose,metadata,dispose}`：模型高1、前向+Z；pose 提供 `update/sit/stand/amount/contactY/duration`，可选 `setLocomotion`。顶层 `dispose()` 表示角色自己释放GPU资源；若未提供，核心在停止pose后遍历释放模型资源。

`assets/original-fox.glb` 是独立可导入资产，含 `idle/walk/sit/stand` 四段节点关节动画，约146KB，无外链/贴图。其他引擎导入后先检查坐标轴、光照与动画播放。**GLB坐起已经烘焙根高度补偿，不能再重复减 contactY**；JS工厂由房间控制器补偿，二者不同。可运行 `node tools/export-character.mjs` 重新导出。

## 多座位与悬停提示（v2.2 新增）

可坐家具：沙发 `sofa`、黄色软凳 `ottoman-a`、绿色软凳 `ottoman-b`。点击可坐下/起立，坐在 A 上点击 B 会自动起立换座；**无论坐在哪个座位，按 WASD/方向键即自动起立**，起立落地后继续向按下的方向走。`getState()` 新增 `seatId`（`null`=站姿）。悬停到沙发/软凳/台灯会弹出「坐下/起立」「打开/关闭灯光」气泡，**只提示、点击才执行**；提示为纯 DOM 元素（`role="tooltip"`、`pointer-events:none`），随房间销毁自动移除，不依赖 UI 皮肤层。家具被移动/旋转后座位落点会随矩阵自动重算，无需宿主干预。座位换算在 `seats.mjs`（`SEATS` 表 + `fitSeat`），可单独测试；想加第四个可坐家具，往 `SEATS` 加一项并给对应家具 Group 打上 `interaction:'seat'` / `seatId` 标记即可。

动画契约：`idle/walk` 循环、`sit`（1.45s）/ `stand`（1.2s）播一次并保持末帧；坐/立的阶段标签（前倾准备/沉髋蓄力/屈髋屈膝/抱膝收敛/落臀缓冲/落座回稳/坐稳；起立前倾/撑膝发力/蹬腿伸髋/起身回正/挺身站稳/站立）可由 `pose.stage` 读出，供宿主同步 UI 文案。行走时根节点带有竖直起伏与骨盆侧移轨道，直接导入 GLB 同样生效。
