# 两轮自检与修复 · v2.39.1

日期：2026-11-11。范围为 3D 仓鼠屋及独立测试工具。使用隔离临时账号进行双端验证，保留用户实测 A/B 存档及历史报告。

## 第一轮：状态、异常和存档边界

先新增可复现的回归用例，确认以下四项在修复前均失败，再修复并复测：

1. 主人结束参观后，晚到的旧列表可能短暂重新显示客人。增加已结束邀请过滤和重复操作保护。
2. 主人点击“去看看”时，如果切换楼层失败，事件处理函数抛错且没有显示原因。现在捕获异常并保留可见提示，恢复按钮。
3. 客人换楼层时旧心跳占用请求，晚到的旧失败响应可能影响新楼层甚至结束参观。现在切换或进入后台会取消旧请求，新楼层独立同步，旧响应不得覆盖当前状态；请求超时仍会释放重试机会。
4. 加载参观失败时，错误写入已关闭的好友面板，用户看不到原因。失败后恢复邀请面板和可重试提示，并恢复自己小屋的显示。

第一轮针对性检查 42 项通过，包括好友聊天生命周期、参观请求、数据库恢复和楼层存档；真实 MySQL 好友集成测试 1 项通过，验证授权、隐私、撤销、楼层和原存档不变。

## 第二轮：多设备布局和多人场景

先复现，再修复以下五项：

1. 多个长昵称同时来访时，提示文字撑高面板，小屏幕会遮挡底部操作。限制面板总高度，列表保留连续滚动，多人提示显示简短汇总。
2. 高度 501–540 像素的横屏中，来访面板与“看全屋、找宠物”的断点不一致，发生重叠。统一断点并保留间距。
3. 打开个人主页时来访面板仍在上方争抢操作。现在个人主页、商店和装修期间隐藏来访控件，关闭后恢复。
4. 心跳返回顺序变化会把多个客人的位置交换；其他人离开也可能导致剩下的人移动。现在按稳定身份处理，并保留仍可站立的位置。
5. 主人将家具移动到客人位置后，客人列表没有变化，因此不重新选位置。现在检查当前位置是否被家具挡住，优先在可用位置重新安排，并补全四角碰撞检查。

第二轮针对性检查 14 项通过，包括 320×480、568×320、900×520、768×1024、1366×768 布局，12 位长昵称访客的滚动操作，模型位置稳定性、资源清理，以及花园和厨房的实际 3D 操作检查。
