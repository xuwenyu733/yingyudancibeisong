# 来访宠物与互动 · v2.41.0

本版接续 v2.40.0 的安全与性能加固。前端为 2.41.0，专用后端为 1.8.0；数据库结构仍为 1.6.2，没有新增迁移，也不清理已有装修、积分或手机反馈。

## 玩家可以使用的功能

- 客人进入朋友家后，显示自己当前选择的宠物、宠物名字、帽子、围巾、背包和成长体型。每个账号只有一只自己的宠物；其他角色是已接受邀请的朋友。
- 客人点击家具，由自己的宠物走过去互动。已接入座位、阅读架、茶桌、盆栽、星灯、小火箭和台灯。主人与客人看到同一个服务端确认的动作。
- 点击同一件正在互动的家具可以结束，点击另一件可以切换；页面也提供“结束互动”按钮。
- 点击主人宠物，或者“和主人打招呼”，客人的宠物走近，双方转向彼此，主人做开心回应。主人忙碌、离线、坐着或不在同一层时会给出提示。
- 主人与客人不能抢占同一个座位。现有每件可坐家具使用一个真实座位位置，不把单座模型伪装成多座。
- 客人切楼层、回家或被主人结束参观时，角色和动作会清理。主人保存新的装修后，客人会刷新该层的公开布置；未确认的装修草稿不作为公开存档传播。
- 老存档没有单独摆放坐标时，已经摆出的商店家具仍可显示给客人，仓库里的物品不会公开。

## 权限与同步

公开外观由服务器从当前存档生成，只包含显示所需字段，不发送完整账号、积分、学习秒数或会话凭据。客人请求只表达家具互动、打招呼或取消，不能指定其他玩家、任意坐标、奖励或写入主人的装修。

`visit-presence` 和 `host-presence` 返回包含主人、客人及动作的快照；`visit-action` 校验邀请、好友关系、拉黑状态、楼层、家具和座位占用。主人喝茶的座位同样由服务器预留。家具移动或收纳会使目标指纹失效，已有动作会停止。

窗口使用独立会话及递增序号；新窗口接管后旧窗口不能抢回控制。快照包含 `runtimeId`、`revision`、`serverNow` 和 `homeRevision`，用于过滤乱序响应及识别服务重启。

动作和占座属于临时状态，不写入银行或装修存档。服务重启后动作结束，重新连接后恢复在线状态。当前实现面向单实例部署；部署多个服务实例前，需要把临时状态和限流迁到共享存储。

## 本轮修复的联调问题

1. 宠物点击检测曾引用不存在的 `actor.group`，已改为实际模型根节点。
2. 坐下后控制器坐标仍在椅前，公开位置现使用角色实际位置；起身后另一端能同步站起。
3. 寻路和移动检查曾重复增加碰撞余量，导致靠近沙发时失败，现统一使用相同边界。
4. 服务器预约成功但本地走不到时，会释放占用；首次响应期间发生的失败取消会排队执行，不会被忙碌标记吞掉。
5. 主人已经坐着时补登记座位不再再次切换坐姿；喝茶使用服务器确认的座位。
6. 客人页面不会自行触发主人的欢迎、拿礼物或空闲活动。
7. 访客的行走按实际经过时间推进，并用小步检查碰撞，减少低帧率设备走到一半就超时的问题。
8. 多个孩子同时首次入屋曾触发 MySQL 1213 死锁。票据改为仅删除已确定超额的主键，会话上限使用当前读；只对明确死锁且成功回滚的入屋事务做有上限的重试，连接中断或提交结果不确定时不自动重放。30 轮、120 次隔离入屋验证通过，返回会话均有效。
9. 公开布局只包含实际摆放的家具、必要变换和碰撞字段；旧存档中残留的已入库家具坐标、孤立模型定义和装修附加库存字段不再发给客人。可见挂件信息保留，原存档不变。
10. 真实 A/B 旧存档进入时，宠物空闲触碰记录可能在服务器确认入屋期间写入本机，造成误报存档冲突。现暂停确认期间的自动互动记录、礼物过期收纳和自动备份；手动备份仍可在普通暂停面板使用，真正的存档冲突检查保持严格；入屋时发生真实冲突会保留导出与恢复入口。隔离旧存档加延迟响应的兑换回归，以及真实 A/B 进入、重载和商店打开关闭均已通过。
