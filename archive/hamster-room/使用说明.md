# 仓鼠房间使用说明

## 启动预览

1. 安装 Python 3，并确保命令行能执行 `python`。
2. 双击本目录的 `StartPreview.cmd`。程序会启动本地服务并打开浏览器，默认地址为 `http://127.0.0.1:8766/`。
3. 如果端口被占用，会尝试后续端口，以命令窗口显示的地址为准。关闭预览时，在该窗口按 `Ctrl+C`。

所需 Three.js 模块已放在 `vendor/`，模型位于 `assets/`；运行时无需 npm、在线 CDN 或额外 Python 包。请保留整个目录，通过本地服务打开，勿直接双击 `index.html`。

## 操作

- 点击台灯：切换暖光。
- 点击沙发：仓鼠寻路到沙发前方，跳上座面并坐下；再次点击会站起并返回地面。
- 点击可到达的地面：仓鼠绕开家具走向目标；坐着时会先离开沙发。障碍内或不可达的位置不会强行穿越。
- 方向键或 `WASD`：在地面按屏幕方向移动。
- 空格：停止当前地面行走，取消走向沙发。

相机保持固定斜俯视角。动作过程中重复点击沙发会更新坐下/站起意图，过渡到安全阶段后执行。

## 装修与保存

1. 点击“装修”；若仓鼠正在沙发上，会先等它起身落地站稳，装修期间暂停宠物移动。
2. 点击家具选中后拖动，默认按 **0.1 米**吸附；取消“摆放吸附”可连续摆放。吸附只参与计算，普通、选中和拖动状态都不显示地面网格、碰撞线框或选中轮廓。
3. 点击“旋转90°”调整朝向。不合法的位置只通过文字提示；松手后恢复拖动前的位置，旋转失败也会回退。
4. 展开“碰撞盒设置”，独立调整宽、高、深和 X/Y/Z 偏移；这些数值不会改变模型外观。两个开关分别控制“阻挡仓鼠行走”和“参与家具摆放碰撞”。当前面板编辑第一个盒体，代码可为一件家具配置多个盒体。
5. 台灯可放在边柜或矮桌的有效台面区域；已建立支撑关系后，移动、旋转该家具会带着灯一起变化。移出台面后，灯回到地面高度。
6. “完成保存”将布局写入当前浏览器的 `localStorage`；“取消”恢复本次进入装修前的布局。`Esc` 在拖动时取消这次拖动，未拖动时取消本次装修。

本地存档使用 v3 格式（键名 `hamster-room-layout-v3`），包含家具变换、碰撞配置和台灯支撑关系。刷新后会尝试恢复并重新校验；出生点被家具占用时，仓鼠移到安全的沙发接近点。损坏或不适用的存档回到默认布局。存储按浏览器和站点来源隔离，换浏览器或换端口不会共享。该存档尚未连接账号或云端。

## 修改布局与模型

- `layout.js`：集中配置房间尺寸、模型家具的 `position`、`rotation`、`scale` 和颜色。位置为 `[x,y,z]`，Y 向上，+Z 朝房间前方；旋转单位是弧度。
- `COLLIDERS`：独立的局部碰撞配置，使用 `boxes: [{center:[x,y,z], size:[宽,高,深]}]`，以及 `blocksNavigation`、`blocksPlacement` 开关。碰撞尺寸不从渲染模型包围盒推断；接口使用模型局部坐标，面板会计入家具缩放。
- `SOFA`：沙发模型局部坐标中的座面锚点 `seat`、可接受的座面区域 `seatRegion`、沙发前方落点 `approach`。更换沙发模型时需要重新标定，避免射线误取靠背或扶手。
- 原 GLB 的前向为 **+X**。当前沙发及宠物通过绕 Y 轴旋转 `-Math.PI / 2` 朝向房间前方；替换模型时请检查朝向。
- `decor.js`：程序生成的墙面、柜架及其他装饰。
- `room.js`：场景和接口；`decoration.js`：装修操作；`layout-manager.js`：布局事务、台灯联动与存档；`colliders.mjs`：摆放碰撞；`navigation.mjs`：寻路；`pet-pose.js`：程序动作。

家具以独立 `Object3D` 保存在 `Map` 中。摆放采用带高度检查的旋转盒体 SAT 检测，贴边和正常台面支撑允许；寻路采用按仓鼠安全半径保守膨胀的 AABB，可能比模型外形留出更多余量。提交还会检查房间边界、宠物位置、沙发落点及可达通道。

**新增家具时，需同步注册家具 ID 与 `COLLIDERS` 配置。** 移动已有家具请使用布局接口，使碰撞、座面和支撑关系一起更新。

## 留给 App 的接口

页面加载完成后，可通过 `window.HamsterRoom` 调用场景。以下命令分别演示不同操作，请按需单独执行：

```js
window.HamsterRoom.setLamp(false);
window.HamsterRoom.toggleSofa();
window.HamsterRoom.walkTo(0, 2);
const table = window.HamsterRoom.getFurniture('table');
const layout = window.HamsterRoom.getLayout();
await window.HamsterRoom.setDecorationMode(true);

// 仓鼠需 idle 且当前没有拖动；失败返回 false 并回滚。
window.HamsterRoom.setFurnitureTransform('table', {
  position: [-0.55, 0, 0.87],
  rotation: [0, 0, 0],
  scale: 1.9,
});

// 局部坐标；这里只演示开关，省略的尺寸和偏移保持原值。
window.HamsterRoom.setFurnitureCollider('rug', {
  blocksNavigation: false,
  blocksPlacement: false,
});
window.HamsterRoom.setDecorationMode(false); // 相当于“完成保存”
```

场景事件从画布冒泡，可在页面监听：

```js
window.addEventListener('room-event', (event) => {
  const { type, ...data } = event.detail;
  console.log(type, data);
});
// ready、lamp-change、pet-state、path-blocked、decoration-mode
// layout-change、layout-invalid、layout-saved、layout-save-failed
```

这层接口用于后续 uni-app WebView 接入，**尚未完成 App 真机接入**。代码在存在 `window.uni.postMessage` 时尝试转发事件；宿主还需完成 SDK、桥接就绪和消息接收验证。卸载时调用 `window.HamsterRoom.dispose()`。当前仅持久化本机房间布局；账号、装修库存、积分、交易及云端存档仍由 App 和后端实现。

当前竖屏镜头会裁去部分地板外角，以便主要家具保持足够大小；横屏显示完整房间。

## 素材与当前限制

- 交付模型使用优化副本，总大小由约 **63.69 MB 降至 7.74 MB**，合计约 **26 万三角形**；用户提供的原图与原始 GLB 未改动。
- 仓鼠原模型是静态网格，没有骨骼。坐起动作通过虚拟髋、膝和腰部关节生成 **6 个 morph 姿态**，按前倾、屈膝、落臀、坐稳和蹬腿等阶段播放；头脸与眼镜在目标姿态中保持刚体形状。步态与跳跃也由程序驱动，**不是原模型自带的骨骼动画**。
- 房间按用户新参考图的空间关系重建。二维插画与三维相机的透视不同，当前布局并非逐像素复刻。
- 桌面浏览器可用于检查交互；移动端的帧率、内存、加载时间、触摸及 WebView 兼容性仍需真机测试。

## 与 uni-app App（hamster-app）联调

桌面另有项目 `~/Desktop/hamster-app`：**App 壳**（不做微信小程序）。

- App 打包：房间复制到 `hamster-app/hybrid/html/room/`，用本地 WebView 打开。
- H5 联调：仍可用本预览服务；改房间后执行 `npm run sync:room`。
- 通过 URL `bootstrap` / `applyHostActions` 下发积分兑换后的摆放与外观。

房间侧接口：`applyHostActions`、`setOutfitTint`、`message` 监听。
